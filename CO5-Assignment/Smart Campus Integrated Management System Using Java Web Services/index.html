The Smart Campus architecture decouples departmental applications. The Student Information Service Provider publishes its standard WSDL contract to the Service Registry. When a consumer such as the Attendance or Library app needs to verify a student, it discovers the endpoint and invokes getStudentById() using standard SOAP envelopes.

1. Service Provider

The department or application that creates, publishes, and maintains a web service. In our system, the Central Academic Office implements StudentInformationServiceImpl and publishes it via an embedded HTTP endpoint.

2. Service Registry

A searchable directory where available web services, their operational endpoints, and machine-readable WSDL descriptions are cataloged. Enables loose coupling by allowing consumers to discover services dynamically.

3. Service Consumer

The client application that discovers the service contract and invokes exposed operations. The Attendance, Exam, Library, and Fee apps bind to the provider using JAX-WS dynamic proxies.

Advantages of Java Web Services in University Management
Enterprise SOA Benefits

Heterogeneous Interoperability

Connects applications built on different technologies (Java, .NET, Python, Node.js). By utilizing universal XML and SOAP protocols, departments freely exchange data without proprietary lock-in.

High Scalability

New departments (e.g., Hostel, Sports, Alumni) can be plugged into the campus platform anytime without modifying existing services. Each departmental service can be scaled or updated independently.

Seamless Information Sharing

Eliminates duplicate student data entry across offices. When a student updates their address or phone number, the change immediately reflects in Attendance, Library, and Fee departments.

WSDL Document Explorer

Web Services Description Language (WSDL 1.1) contract for StudentInformationService

Explain WSDL Elements
Standard WSDL Structure

<types> – Data Type Definitions (XML Schema / XSD)

Defines the structure of the data transmitted between provider and consumers. Specifies complex types such as student (containing studentId, studentName, department, etc.) and wrapper elements for requests and responses.

<xsd:complexType name="student"> <xsd:sequence> <xsd:element name="studentId" type="xsd:string"/> ...

<message> – Input and Output Parameters

Defines the abstract messages exchanged in an operation. For instance, getStudentByIdRequest defines the parameter payload sent to the service, and getStudentByIdResponse defines the returned data.

<portType> – Abstract Service Interface

Analogous to a Java Interface. Specifies the callable operations (such as getStudentById and getAllStudents) and associates them with corresponding input, output, and fault messages.

<binding> – Protocol and Encoding Format

Specifies how the abstract portType operations are serialized over the wire. In our case, it specifies SOAP 1.1 Document/Literal style over HTTP transport.

<service> – Physical Endpoint Location

Specifies the concrete network address (URI) where the service can be invoked. In our setup, this is located at http://localhost:8888/ws/student.

StudentInformationService.wsdl (SOAP 1.1) 
<?xml version="1.0" encoding="UTF-8"?>
<definitions 
    xmlns="http://schemas.xmlsoap.org/wsdl/"
    xmlns:soap="http://schemas.xmlsoap.org/wsdl/soap/"
    xmlns:tns="http://service.smartcampus.com/"
    xmlns:xsd="http://www.w3.org/2001/XMLSchema"
    targetNamespace="http://service.smartcampus.com/"
    name="StudentInformationService">

    <!-- 1. DATA TYPES (XML SCHEMA DEFINITION) -->
    <types>
        <xsd:schema targetNamespace="http://service.smartcampus.com/" elementFormDefault="qualified">
            <xsd:complexType name="student">
                <xsd:sequence>
                    <xsd:element name="studentId" type="xsd:string"/>
                    <xsd:element name="studentName" type="xsd:string"/>
                    <xsd:element name="department" type="xsd:string"/>
                    <xsd:element name="year" type="xsd:string"/>
                    <xsd:element name="email" type="xsd:string"/>
                    <xsd:element name="mobileNumber" type="xsd:string"/>
                    <xsd:element name="admissionStatus" type="xsd:string"/>
                    <xsd:element name="cgpa" type="xsd:double"/>
                </xsd:sequence>
            </xsd:complexType>

            <xsd:element name="getStudentById">
                <xsd:complexType>
                    <xsd:sequence>
                        <xsd:element name="studentId" type="xsd:string"/>
                    </xsd:sequence>
                </xsd:complexType>
            </xsd:element>

            <xsd:element name="getStudentByIdResponse">
                <xsd:complexType>
                    <xsd:sequence>
                        <xsd:element name="student" type="tns:student" minOccurs="0"/>
                    </xsd:sequence>
                </xsd:complexType>
            </xsd:element>

            <xsd:element name="getAllStudents">
                <xsd:complexType/>
            </xsd:element>

            <xsd:element name="getAllStudentsResponse">
                <xsd:complexType>
                    <xsd:sequence>
                        <xsd:element name="studentList" type="tns:student" minOccurs="0" maxOccurs="unbounded"/>
                    </xsd:sequence>
                </xsd:complexType>
            </xsd:element>

            <xsd:element name="StudentNotFoundFault">
                <xsd:complexType>
                    <xsd:sequence>
                        <xsd:element name="faultInfo" type="xsd:string"/>
                        <xsd:element name="message" type="xsd:string"/>
                    </xsd:sequence>
                </xsd:complexType>
            </xsd:element>
        </xsd:schema>
    </types>

    <!-- 2. MESSAGES -->
    <message name="getStudentByIdRequest">
        <part name="parameters" element="tns:getStudentById"/>
    </message>
    <message name="getStudentByIdResponse">
        <part name="parameters" element="tns:getStudentByIdResponse"/>
    </message>
    <message name="getAllStudentsRequest">
        <part name="parameters" element="tns:getAllStudents"/>
    </message>
    <message name="getAllStudentsResponse">
        <part name="parameters" element="tns:getAllStudentsResponse"/>
    </message>
    <message name="StudentNotFoundFault">
        <part name="fault" element="tns:StudentNotFoundFault"/>
    </message>

    <!-- 3. PORT TYPE (CONTRACT) -->
    <portType name="StudentInformationService">
        <operation name="getStudentById">
            <input message="tns:getStudentByIdRequest"/>
            <output message="tns:getStudentByIdResponse"/>
            <fault name="StudentNotFoundFault" message="tns:StudentNotFoundFault"/>
        </operation>
        <operation name="getAllStudents">
            <input message="tns:getAllStudentsRequest"/>
            <output message="tns:getAllStudentsResponse"/>
        </operation>
    </portType>

    <!-- 4. PROTOCOL BINDING (SOAP 1.1 / HTTP) -->
    <binding name="StudentInformationServicePortBinding" type="tns:StudentInformationService">
        <soap:binding transport="http://schemas.xmlsoap.org/soap/http" style="document"/>
        <operation name="getStudentById">
            <soap:operation soapAction="http://service.smartcampus.com/getStudentById"/>
            <input><soap:body use="literal"/></input>
            <output><soap:body use="literal"/></output>
            <fault name="StudentNotFoundFault">
                <soap:fault name="StudentNotFoundFault" use="literal"/>
            </fault>
        </operation>
        <operation name="getAllStudents">
            <soap:operation soapAction="http://service.smartcampus.com/getAllStudents"/>
            <input><soap:body use="literal"/></input>
            <output><soap:body use="literal"/></output>
        </operation>
    </binding>

    <!-- 5. SERVICE ENDPOINT -->
    <service name="StudentInformationService">
        <port name="StudentInformationServicePort" binding="tns:StudentInformationServicePortBinding">
            <soap:address location="http://localhost:8888/ws/student"/>
        </port>
    </service>
</definitions>

StudentServiceConsumer.java (Real JAX-WS Java Consumer Code) 
// Obtain WSDL URL and QName
URL wsdlUrl = URI.create("http://localhost:8888/ws/student?wsdl").toURL();
QName serviceQName = new QName("http://service.smartcampus.com/", "StudentInformationService");

// Create standard JAX-WS service proxy
Service service = Service.create(wsdlUrl, serviceQName);
StudentInformationService studentService = service.getPort(StudentInformationService.class);

// Invoke operation getStudentById over SOAP
Student student = studentService.getStudentById("STU-1001");
System.out.println("Verified Student: " + student.getStudentName() + " | Dept: " + student.getDepartment());
