1. Service Consumers

Doctor, lab, pharmacy, and patient applications do not connect directly to MySQL. Instead, they consume SOAP services using WSDL contracts, promoting loose coupling and platform independence.

2. Java Web Service Provider

HealthcareInformationServiceImpl handles incoming XML envelopes, verifies input, runs business logic, and returns formatted SOAP response XML or SOAP Faults.

3. JDBC Mechanism

DatabaseConnection.java loads credentials safely and executes parameterized PreparedStatement queries to prevent SQL injection and ensure maximum database throughput.

4. Centralized MySQL

medic_connect_db serves as the single source of truth, enforcing referential integrity with foreign keys and ACID transactional consistency across all hospital modules.

SOAP Message Structure Explorer

Anatomy of SOAP 1.1 / 1.2 XML: Envelope, Header, Body, and Fault elements

1. Envelope

Root element identifying the XML document as a SOAP message. Defines XML namespaces and encoding rules.

2. Header

Optional container for application-specific metadata such as security credentials, tokens, or transaction IDs.

3. Body

Mandatory payload container holding either the operation request parameters or the returned clinical data.

4. Fault

Standard error reporting sub-element inside Body, containing faultcode, faultstring, and detailed exception XML.
